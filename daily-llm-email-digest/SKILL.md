# 每日 LLM 邮件简报

目标是交付能长期运行的本地程序，而不只是当天的一封摘要。[scripts/llm_digest.py](scripts/llm_digest.py) 是一个已运行过的 Python 标准库实现，可作为起点；按用户的系统、时区、信息源和已有邮件配置调整。

## 实施流程

1. 查看用户提到的现有邮件程序，确认 SMTP 主机、端口、发件人、收件人及凭据读取方式。只输出配置键名和是否已配置，不在终端、日志、代码库或回答中展示密钥。若复用 `~/.vocab_config.json`，保持它的权限为 `0600`。
2. 选择可访问的来源，至少覆盖模型发布和研究论文。示例脚本读取 OpenAI 新闻 RSS、Google AI RSS、Google News 搜索 RSS 和 arXiv API。上线前实际验证端点和数据格式；接口与新闻来源可能变化。按发布日期筛选，保留原文链接，并将预印本标为预印本。
3. 为每条动态提供简短中文解释，另挑选原文中确实出现的技术概念作通俗说明。将标题和摘要作为生成依据，提示模型不得补充未经来源证实的数字或结论。若 AI 接口失败，回退到明确标注的原文摘要，不把英文摘要伪装成中文解释。
4. 去重并记录已发送的链接。只在 SMTP 成功后写入状态，避免发送失败导致漏报。抓取全部失败时应报错而非发送空白邮件；部分来源失败可继续并在邮件中注明。
5. 先运行 `preview`，检查真实抓取结果、主题相关性、中文解读和原文链接。修正新闻噪声、输出截断或模型编造问题后再发送。只有用户已授权发信时才运行 `send`。
6. 如果用户要求每天自动发送，安装对应系统的调度任务，并确认任务已加载。macOS 可使用 `~/Library/LaunchAgents` 的 `StartCalendarInterval`；Linux 可使用 cron 或 systemd timer。使用绝对解释器与脚本路径，明确时区。调度器通常不会继承交互式 shell 的 API Key，应从权限为 `0600` 的私有配置或系统凭据存储读取，避免让定时任务加载整个交互式 shell。
7. 验证脚本语法、调度配置和一次完整发送流程，检查收件结果及状态文件。报告实际发送时间、下次运行时间、日志位置，以及机器需要开机或登录等运行条件。

## 复用脚本时要改的地方

- `MAIL_CONFIG`：默认读取 vocab 的 Gmail 配置；其他邮件程序应按其配置方式接入。
- `DIGEST_CONFIG`：示例脚本从 `OPENAI_API_KEY` 或私有 JSON 文件读取 Key；不要把 Key 提交到仓库。
- `FEEDS`、`NEWS_SOURCES`、`KEYWORDS`：按用户关注的研究方向调整，并保持新闻来源质量。
- `TZ`、调度时间与路径：按用户所在地和运行环境设置。
- `ai_explain()`：模型和响应格式应按当前官方 API 文档核对。输出必须校验；失败时按上面的回退方式处理。

创建 Skill 本身不意味着获准在用户机器上发邮件、安装计划任务或保存凭据；这些行为以当次用户请求和已有授权为准。
