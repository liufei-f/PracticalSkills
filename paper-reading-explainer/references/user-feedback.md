# 本次用户反馈与可复用教训

## 真实反馈顺序

用户最初要求：“读这篇文章，把其中的方法和结论一一告诉我，另外，每张图片也要告诉我在说什么。仔细阅读。”

首次回答虽然覆盖方法、数字、评分、图和限制，但没有先建立具体概念和数据来去，随后收到这些反馈：

1. “你没讲‘世界’这个概念的意思，直接用太抽象了，我不懂。你没讲这篇文章用了什么数据，产生了什么数据。”
2. “还是没看懂，用简洁的人话，再描述一遍这篇文章的中心含义。”
3. “这个有标准答案的练习场，是怎么做的，用简洁的人话解释，但是不要忽略重要事实。”
4. “genotype和phenotype全部是simulated吗，全是假的吗。”

不要把这些反馈理解为用户不需要严谨性。用户要求的是：先理解，再展开；少用未经解释的词；重要事实不能因通俗化而消失。

## 应当改变的决策

- “仔细阅读”规定阅读深度，不代表开头就应给一篇很长的专业综述。
- 不要先使用 world 再在追问中解释。最先说清楚它是一个数据集连同隐藏生成规则。
- 介绍研究时主动交代真实输入和生成输出；不要只列最终数据尺寸。
- 用户说不懂时，重写概念骨架，而不是增加更多表格、名词和细节。
- 用户追问模拟性质，表明之前的数据真实性说明不够突出。应把事实来源放在主体，而非埋在限制中。
- 对这位用户，优先用简明中文说明，保留其问题中的 genotype、phenotype 等词并配中文释义；不要假定知道术语就理解了研究设计。

## 泛化边界（用户新增反馈）

用户补充：“不要僵化于这一篇文章。”

保留本次追问所揭示的理解缺口，不保留该论文作为技能的默认任务模型：

- 从“世界没解释”抽取的是“先定义核心概念”，不是要求每篇都有世界、隐藏规则或AI。
- 从“用了什么、产生什么数据”抽取的是“交代研究材料与作者贡献”，不是要求理论论文也有数据生成流程。
- 从“全是模拟的吗”抽取的是“明确证据的来源与性质”；只有相关论文才需细分模拟、真实数据和模板。
- “标准答案”“评分”“训练”“因果”都是具体研究可能具有的要素，不是所有论文的必答项。
- 删除原先单篇论文的详细案例与固定数字，防止后续实例误套。历史反馈中的原话仅用来理解表达需求。

## 跨类型检查

以下是检查任务，不是预设答案或固定输出结构：

- 实验论文：能否说清对象、干预/对照、测量结果，且不把实验结果当作理论证明？
- 观察研究：能否说明样本和比较方式，并区分关联与因果？
- 理论论文：能否用人话解释问题、假设和定理，不强塞“用了什么数据”？
- 方法/系统论文：能否区分作者新增部分、已有资源以及验证证据，不默认一定训练AI？
- 定性研究/综述：能否说明材料选择与综合逻辑，不套用模型评分？
- 任一类型：用户说不懂时，是否换成更具体的解释；要求逐图时，是否确实阅读并覆盖子图？
